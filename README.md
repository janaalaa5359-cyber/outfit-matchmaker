# Outfit Matchmaker 👗
**DS432: Web Development for Data Science – Group Homework 2**
Taibah University · College of Computer Science and Engineering · Department of AI and Data Science

Outfit Matchmaker coordinates clothes, bags and shoes by occasion, colour and style.
In Homework 2 the website became a **Flask** application: the form is checked on the server,
every valid look is saved in **SQLite**, and the match score is predicted by a trained
**scikit-learn** model that is also available as a deployed JSON API.

## Dataset and model summary
| | |
|---|---|
| **Dataset** | **Demonstration dataset** (2,000 rows), generated by `train_model.py` and saved in `data/outfit_demo_dataset.csv`. Random outfit combinations are labelled with the Homework 1 colour-harmony / dress-code rules plus random noise (to imitate different people's ratings). It is *not* real user data. |
| **Input features** | `occasion`, `mainColor`, `mainPiece`, `season`, `style` (categorical, one-hot encoded) and `budget` (number, SAR) |
| **Prediction target** | `match_score` – how well the outfit matches (0–100) |
| **Model** | `RandomForestRegressor` (150 trees) in a scikit-learn `Pipeline` with `OneHotEncoder` |
| **Evaluation** | 80/20 train–test split. **Test MAE = 3.59 points** (R² = 0.625). A baseline that always predicts the average score has MAE = 5.80. |
| **Model artifact** | `model/outfit_model.pkl` (loaded once when Flask starts), metrics in `model/metrics.json` |

The suggested partner piece, shoes and bag still come from the colour-harmony rules
(`outfit_rules.py`); the **match score** is the ML prediction.

## How to run locally
```bash
python -m venv venv
# Windows: venv\Scripts\activate      Mac/Linux: source venv/bin/activate
pip install -r requirements.txt
python train_model.py        # optional: re-creates model/outfit_model.pkl
python app.py
```
Open http://127.0.0.1:5000. The SQLite database is created automatically at `instance/outfits.db`.

Test the API (in a second terminal while the app is running):
```bash
python test_api.py                                   # local
python test_api.py https://YOUR-APP-NAME.onrender.com   # deployed
```

## Pages and API
| Route | Method | Purpose |
|---|---|---|
| `/` | GET, POST | Home page and form. POST validates on the server; valid looks are scored by the model and saved. Invalid input shows an error and nothing is saved (HTTP 400). |
| `/records` | GET | All saved looks, read from SQLite with `Look.query` |
| `/about` | GET | About the project |
| `/predict` | POST | JSON in → JSON prediction out. Returns **400** with error details for invalid input. |
| `/health` | GET | Service status and whether the model is loaded |

Example:
```json
POST /predict
{"occasion": "wedding", "mainColor": "burgundy", "mainPiece": "dress",
 "season": "winter", "style": "classic", "budget": 800}

200 → {"match_score": 78, "suggested": {"complement": "Beige long coat",
       "shoes": "Gold heeled sandals", "bag": "Gold clutch"}, ...}
```
Allowed values – occasion: wedding, work, university, family, outing, sport ·
mainColor: black, white, beige, navy, grey, red, pink, green, blue, mustard, burgundy ·
mainPiece: top, dress, abaya, trousers, skirt · season: summer, winter, spring ·
style: classic, modern, minimal, bold · budget: 50–10,000.

## Server-side validation rules
- Look name 3–40 characters · occasion, colour, piece, season and style must be allowed values
- Budget must be a number between 50 and 10,000 SAR
- A dress or abaya cannot be chosen for sport · at least one of shoes / bag / accessory
